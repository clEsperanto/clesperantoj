# Contributing to clesperantoJ

Thanks for considering contributing! This document covers the project layout, what you should
and shouldn't edit by hand, and the checks to run before opening a pull request.

For build prerequisites and instructions, see [BUILD.md](BUILD.md) first.

## Project layout

```
native/clesperantoj/   C++ wrapper around CLIc (CMake project), hand-written .cpp/.hpp
src/main/java/          Hand-written Java: high-level API (core/), presets (presets/),
                         optional integrations (imglib2/, imagej/)
src/main/java/net/clesperanto/kernels/   Generated Tier1..Tier8.java — produced by an
                         automated bot from the CLIc kernel definitions. Do not edit manually;
                         changes will be overwritten on the next sync.
src/gen/java/            Generated by the JavaCPP `parse` goal from the presets in
                         src/main/java/net/clesperanto/presets/. Do not edit manually;
                         regenerated on every `mvn generate-sources`.
src/test/java/           JUnit tests. Require a working OpenCL device (a GPU driver or POCL
                         for CPU-only OpenCL) to run.
```

If you need to change generated code, change its source instead:
- `src/gen/java/**` → edit `src/main/java/net/clesperanto/presets/{jclic,kernelj}.java`.
- `src/main/java/net/clesperanto/kernels/**` → the change belongs upstream in
  [CLIc](https://github.com/clEsperanto/CLIc); it will flow down through the automated sync.

## Versioning

`pom.xml` has two version numbers that must be kept in sync manually:
- `<version>` (project artifact version)
- `<clic.version>` (the CLIc git tag fetched and built by CMake)

When bumping `clic.version` to track a new CLIc release, also bump the project `<version>`
in the same pull request.

## Backend selection

CLIc supports OPENCL (default), CUDA, and METAL backends. This is controlled by the
`clic.backend` Maven property, forwarded as the `CLE_BACKEND` environment variable to the
native CMake build:

```bash
mvn install                          # defaults build to OPENCL
mvn -Dclic.backend=CUDA install      # build CUDA backend
mvn -Dclic.backend=METAL install     # build METAL backend
```

If you touch the `exec-maven-plugin` (`cppbuild` execution) or `native/clesperantoj/cppbuild.sh`,
make sure this property still reaches CMake — it is the only place the backend choice is wired
through the build. 

## Reporting issues

Use the [GitHub issue tracker](https://github.com/clEsperanto/clesperantoj_prototype/issues)
for bugs and feature requests, or the [image.sc forum](https://forum.image.sc/) for usage
questions.

Do not hesitate to reach out for any question or if you which to contribute!
